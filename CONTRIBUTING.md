# Contributing

Thanks for your interest in contributing. A few guidelines help keep changes easy to review:

1. **Keep changes focused.** Make each pull request address one issue or one logical change, and describe what it does and why in the PR description.
2. **Test your changes.** Run the existing tests or checks before opening a pull request, and add tests for new behaviour where practical.
3. **Respect the existing style.** Follow the conventions already used in the code and documentation, and keep commit messages short and descriptive.
