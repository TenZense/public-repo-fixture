# Contributing

Thanks for your interest in contributing. To keep reviews quick and the history easy to follow:

1. **Keep changes focused.** Make each pull request address one thing, and describe what it changes and why.
2. **Check your work before opening a pull request.** Run the existing tests and linters, and add or update tests for any behaviour you change.
3. **Write clear commit messages.** Use a short summary line in the imperative mood (for example, "Fix typo in installation guide"), followed by a body that explains the reasoning when it isn't obvious.
