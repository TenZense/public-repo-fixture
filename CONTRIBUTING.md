# Contributing

Thanks for your interest in contributing. To keep changes easy to review:

1. **Keep changes focused.** Each pull request should address one thing, such as a single fix or a single addition, so it can be reviewed and reverted on its own.
2. **Describe what and why.** Explain the problem a change solves and how you verified it in the pull request description.
3. **Follow the existing style.** Match the formatting, naming, and conventions already used in the surrounding code and documentation.
