# Contributing

Thanks for your interest in contributing. To keep changes easy to review:

1. **Open an issue or discussion first** for larger changes so the approach can be agreed before significant work begins.
2. **Keep pull requests focused.** Make one logical change per PR, include a clear description of what changed and why, and update related documentation or tests in the same PR.
3. **Follow the existing style and check your work.** Match the conventions already used in the codebase and make sure any tests or linters pass locally before requesting review.
