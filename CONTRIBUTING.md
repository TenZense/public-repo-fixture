# Contributing

Thanks for your interest in contributing! Please keep the following guidelines in mind.

## Guidelines

1. **Open an issue first for significant changes.** Describe the problem or proposal so it can be discussed before you invest time in an implementation. Small fixes (typos, minor docs updates) can go straight to a pull request.

2. **Keep pull requests small and focused.** Each pull request should address a single concern, include a clear description of what changed and why, and avoid unrelated refactoring or formatting changes.

3. **Write clear commit messages and verify your changes.** Use a concise summary line in the imperative mood (e.g. "Fix typo in README"), and make sure any existing tests and checks pass before requesting review.
